# 多点、多障碍物避障对比

对同一组有序点位生成两套规划：红色为移除本任务障碍物时得到的无避障基准，绿色为加入全部障碍物后得到的避障路径。当前点序、关节角和障碍物以 [config/config.yaml](config/config.yaml) 与 [config/scene.yaml](config/scene.yaml) 为准；文档示例不覆盖已保存的点位或场景。

## 同一窗口：双路径执行与场景编辑

实机使用前，先在 [CAN 控制面板](../../tools/control_panel/README.md)完成“CAN 连接”和“机械臂使能”，等待六轴使能确认，再启动交互任务。驱动读取启动时的使能状态；若先启动任务后才使能，应结束旧任务后重新启动。回零不是前置步骤。

更新面板后，启动交互控制入口：

```bash
bash scripts/piperl/build.sh
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py --interactive
```

更新后需要重新打开加载该面板的 RViz，已打开的窗口不会热更新。交互入口默认使用实机域 43，沿用 `multi_point` 的官方驱动/MoveIt 链路和左侧面板，不自动使能或执行；已有完整链路会复用。只允许接入既有链路时，加 `--control-stack attach`；更换实机域用 `--control-domain`。也可直接运行 `scripts/task/obstacle_avoidance/control.py --stack attach`。

新建 RViz 使用 1100×680 初始尺寸，首次加载后适应系统主屏的可用区域；交互与纯虚拟入口一致。可在“窗口”菜单选择“移到主屏幕”或“适应当前屏幕”。全屏侧栏按实际宽高增大字号，正文最高 28 px，按钮和状态最高 30 px，标题最高 36 px；配置与工序连续排列，停止/恢复固定在顶部。小窗口可滚动正文。尺寸档位和窗口操作见 [面板说明](../multi_point/rviz_panel/README.md)。

面板可保留供阻尼急停使用。正常运动中不要点击回零、重置或重复使能；阻尼急停后先结束旧任务，再按控制面板说明重置、使能并重新启动任务。

**运动页**：

配置文件栏下面按规划、预览、执行排列；按钮随字号档位增大，不拉伸填满侧栏：

| 排 | 左侧       | 右侧       |
| -- | ---------- | ---------- |
| 1  | 规划无避障 | 规划有避障 |
| 2  | 预览无避障 | 预览有避障 |
| 3  | 执行无避障 | 执行有避障 |
| 4  | 重播       | 返回单点   |

“停止任务”固定在面板顶部；停止后需要恢复时，同一位置显示“恢复控制”。

1. 启动时自动加载默认点位配置；也可选择其他配置并点击“加载”。两种规划独立运行，只生成对应路径，完成后点击同一列的预览按钮。
2. 每条路径从当前实测位置开始，依次经过配置点，因此包括“当前位置 → A”接近段。先规划一条再规划另一条时，会检查配置、模型、运动状态和起点是否仍一致；只保留仍有效的缓存。一条规划失败不会清除另一条仍有效的结果。
3. “预览无避障”切换到红色路径，同时从当前 MoveIt 场景移除本任务的障碍物；“预览有避障”恢复本任务障碍物并切换到绿色路径。其他程序的场景物体始终保留。切换预览本身不移动机械臂。
4. **执行按钮控制实机，并要求对应路径已经预览。** 两套都预览过后，可点击任一执行按钮；它会恢复对应场景并执行那一套原轨迹，不会在执行时换路线或重新规划。“重播”仅播放当前预览。
5. 起点、场景、模型或运动状态变化会阻止执行并要求重新规划。一次执行尝试消耗两套缓存；下一轮重新规划。
6. “返回单点”在同一个窗口恢复官方 MotionPlanning 的拖拽目标和 Plan/Execute；保留当前场景模式并清除多点缓存。停止后若控制门关闭，顶部切换为“恢复控制”；确认恢复后再重新规划，不自动使能或恢复旧轨迹。

终端仍兼容 `p` 规划两套并预览有避障、`b/v` 切换预览、`e` 执行当前预览；面板各按钮使用独立命令。

交互规划使用专用的 `ObstacleControl` / RRTConnect 配置，碰撞边检查参数 `longest_valid_segment_fraction=0.0001`；不修改默认规划器或共享流水线的 TOTG 参数。每段对 MoveIt 通用规划失败、无效轨迹、超时返回码及样条采样碰撞最多尝试 5 次，每次保持同一起点、目标和场景。只有通过复查的轨迹才能预览或执行；取消、场景变化、起点/目标无效等错误直接终止。仍不套用纯虚拟演示的 `--clearance` 扩边。虚拟障碍物的移除不会移除现场实物；两种模式都需要与实际现场相符。

场景页的加载、选择、拖拽、应用和另存为统一见 [RViz 场景编辑](../multi_point/rviz_panel/README.md#场景编辑)。应用新场景会恢复有避障模式，并使两套旧预览失效；重新规划后再执行。

每段 `NNN_inspection.json` 保存各次尝试的 MoveIt 错误或采样复查结果，包括碰撞时间、关节位置及接触物体（服务有返回时）。`99999` 本身只是通用失败码；例如时间参数化后的路径可能被官方 `ValidateSolution` 拒绝，应结合 `official_stack.log` 判断。最多 5 次仍失败时，该次规划不可执行，不保证任意场景都可达。

控制会话日志在 `outputs/tasks/obstacle_avoidance/control/`，各轮 `preview_mode.json` 标记有/无避障模式；执行日志引用对应的预览目录。实机到位、停止和恢复约束见[多点任务说明](../multi_point/README.md)。

## 实测起点越界

若运动页显示“起点越界 · joint2 -2.60°”，表示真实反馈约为 `-0.045361 rad`，小于当前模型的 joint2 下限 `0 rad`。这是生成轨迹前的起点检查失败，与障碍物编辑无关。任务不会将反馈截成 0°、扩大限位、自动使能或生成可执行预览。

未使能时的自然下垂可能造成这一情况；未使能本身并不禁止预览，使能本身也不保证姿态回到模型范围。先按机械臂正常操作流程恢复有效姿态，再点击规划；若反馈与实际姿态不符，需核对零位和模型。不能通过反复规划或修改场景消除越界。

面板只显示一行状态，完整错误可悬停查看，并保留在终端与日志。每轮 `initial_feedback.json` 记录未经修改的六关节反馈、时间戳和模型限位；`result.json` 的 `error_details` 列出全部越界关节。失败后仍可编辑场景或返回单点，但不会绕过官方规划器对起点的检查。

## 纯虚拟对比预览

在项目根目录运行：

```bash
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py
```

不加 `--interactive` 的纯虚拟模式使用独立 ROS 域 87，只启动禁用执行功能的 MoveIt、模型发布器和 RViz，不连接 CAN、不启动实机驱动。实体模型显示虚拟起点 A，不代表实机位置。

启动后自动完成：移除本任务障碍物 → 按点序规划各段基准路径 → 加入全部障碍物 → 检查每段基准碰撞 → 扩大障碍物留边并逐段规划绕行 → 在原始场景中逐段复查 → 播放整条绿色轨迹。各段都从上一段的**实际规划终点**接续，不重置到名义目标，不瞬移回第一个点。

这里的“连续”指各段位置接续并连续回放；每段独立时间参数化，在中间目标处可能减速至停止，不保证以非零速度平滑穿过所有点。纯虚拟对比动画不插入 `hold_seconds` 停留；交互实机执行仍使用配置中的各点停留时间。

| RViz 显示        | 含义                                        |
| ---------------- | ------------------------------------------- |
| 原色实体机械臂   | 第一个配置点的虚拟姿态                      |
| 原色透明机械臂   | 当前选择的整条规划轨迹回放                  |
| 橙色半透明障碍物 | 参与 MoveIt 碰撞检测的几何物体              |
| 绿色线           | 有避障规划的 TCP 路径                       |
| 红色线           | 无避障基准的 TCP 路径；加回障碍物后存在碰撞 |
| 点名标记         | 所有配置目标的 TCP 位置及名称               |

## 终端操作

| 命令           | 操作                                       |
| -------------- | ------------------------------------------ |
| `r`          | 重读点位、场景，重新完成整条路径的对比规划 |
| `b`          | 播放红色无避障基准                         |
| `v` 或 Enter | 播放绿色避障路径                           |
| `s`          | 重读配置并更新场景，使旧预览作废           |
| `c`          | 清除本任务障碍物和预览                     |
| `q` / Ctrl+C | 退出并清理本次启动的进程                   |

任一段规划失败、目标碰撞、路径接续不一致或绕障轨迹复查碰撞，整轮结果作废，不显示部分成功结果或旧轨迹。规划器拒绝某段时最多重试 5 次，点位、场景、容差不变；超时或取消时退出本轮。终端和日志记录失败段号及点名。

## 配置目录与场景

所有配置集中在 `config/`：

| 点位文件                      | 配套场景                     | 用途                        |
| ----------------------------- | ---------------------------- | --------------------------- |
| `config/config.yaml`        | `config/scene.yaml`        | 当前默认点位与障碍物场景    |
| `config/config_simple.yaml` | `config/scene_simple.yaml` | 保留原 A/B 两点、单箱体演示 |

使用原简单场景：

```bash
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py \
  --config scripts/task/obstacle_avoidance/config/config_simple.yaml \
  --scene scripts/task/obstacle_avoidance/config/scene_simple.yaml
```

- 点位按列表顺序访问，可混用关节点和位姿点。位姿点使用米制 `position_m`，朝向可填写 `orientation_xyzw`、度制 `rpy: [Roll, Pitch, Yaw]`，或同时填写两项。两项吻合时采用四元数。详细字段与示例见[多点任务点位配置](../multi_point/README.md#点位配置)。
- 交互入口从实测关节状态出发。纯虚拟对比需要至少两个点，以第一个点作为虚拟起点。若它是笛卡尔点，MoveIt 先求出一组六轴关节角，两条路径从这一组关节角出发。
- 两份随附点位配置的 `velocity_scaling`、`acceleration_scaling` 都是 **0.15**；多点任务随附配置是 **0.30**。字段省略时解析器缺省为 0.10，实际以加载的配置为准。
- 障碍物支持 box `[长,宽,高]`、sphere `[半径]`、cylinder `[高度,半径]`，位置单位 m，坐标系须与配置一致，默认 `base_link`。
- 默认规划时各侧增加 0.025 m 留边；最终显示、碰撞复查使用原始障碍物。可用 `--clearance 0.03` 调整。
- 默认复杂场景每次调用的 `planning_attempts: 1`、`planning_time: 15.0`；任务层保留最多 5 次拒绝重试，避免十次内部尝试导致多障碍物请求过慢。
- 独立规划器使用 TOTG 路径偏移容差 0.0001 rad、重采样间隔 0.05 s，OMPL 的 `longest_valid_segment_fraction` 为 0.0001。不修改实机规划器设置。

所有中间点及首尾点在原始场景和留边场景中都必须无碰撞；整条基准至少一段被挡住才算对比成立，不要求每一段都碰撞。修改点位或场景后，需要重新完成碰撞检查，历史演示结果不能替代本轮结果。若目标点碰撞，应调整点位或场景；若仅留边后碰撞，可检查留边大小。

预览仅管理 `obstacle_avoidance/` 前缀物体，清除时保留其他物体。场景变更必须重新规划；不做动态避障。

## 验证与日志

```bash
# 只检查文件，不启动 ROS
bash scripts/piperl/run.sh --python-only python scripts/task/obstacle_avoidance/run.py --check-config

# 不开窗口，完成对比与碰撞目标拒绝测试后退出
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py --no-rviz --once --self-test
```

域 87 已有节点时拒绝启动，使用 `--domain 97` 等空闲域；对比阶段不接入实机域 43。格式检查不证明可达或无碰撞。

日志：`outputs/tasks/obstacle_avoidance/<会话>/rounds/<轮次>/`。

- `result.json`：点序、段数、各段碰撞检查及采样数、接触连杆和障碍物；`--self-test` 另记录碰撞目标拒绝结果。
- `baseline_trajectory.json` / `avoidance_trajectory.json`：多点模式包含 `point_names` 和有序 `trajectories`；两点模式保留原单条 RobotTrajectory 格式。
- `scene_applied.json` / `planning_scene_with_margin.yaml`：实际场景和规划留边场景。
- 会话目录的 `planner.log`、`rviz.log`：规划器及窗口日志；`process_exit.json` 记录自有进程清理结果。

复查包含轨迹点与点间样条采样，是离散碰撞检查，不是连续碰撞证明。默认虚拟点位尚未实机验收，预览通过不代表实物能安全运行。

本机 MoveIt 在 SIGINT 退出时仍可能发生库内段错误，记录在 `planner.log`。进程清理是否完成以 `process_exit.json` 的 `remaining_pids` 为准；该退出问题尚未修复。

历史面板软件报告的本机路径为 `outputs/validation/scene_editor_validation.json`，不随源码克隆分发。该记录使用隔离仿真，未连接实机驱动，不代表当前点位与场景已经验收。
