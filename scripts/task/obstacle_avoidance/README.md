# 多点、多障碍物避障对比

默认场景包含 **A → B → C → D 四个关节点、三段连续路径、三个箱体障碍物**。对同一组有序点位生成两套规划：红色为移除本任务障碍物时得到的无避障基准，绿色为加入全部障碍物后得到的避障路径。

## 同一窗口：双路径执行与场景编辑

先更新面板，然后启动交互控制入口：

```bash
bash scripts/piperl/build.sh
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py --interactive
```

更新后需要重新打开加载该面板的 RViz，已打开的窗口不会热更新。交互入口默认使用实机域 43，沿用 `multi_point` 的官方驱动/MoveIt 链路和左侧面板，不自动使能或执行；已有完整链路会复用。只允许接入既有链路时，加 `--control-stack attach`；更换实机域用 `--control-domain`。也可直接运行 `scripts/task/obstacle_avoidance/control.py --stack attach`。

**运动页**：

配置文件栏下面固定五排按钮：

| 排 | 左侧               | 右侧       |
| -- | ------------------ | ---------- |
| 1  | 规划无避障         | 规划有避障 |
| 2  | 预览无避障         | 预览有避障 |
| 3  | 执行无避障         | 执行有避障 |
| 4  | 重播               | 停止任务   |
| 5  | 返回单点（占整排） |            |

1. 启动时自动加载默认点位配置；也可选择其他配置并点击“加载”。两种规划独立运行，只生成对应路径，完成后点击同一列的预览按钮。
2. 每条路径从当前实测位置开始，依次经过配置点，因此包括“当前位置 → A”接近段。先规划一条再规划另一条时，会检查配置、模型、运动状态和起点是否仍一致；只保留仍有效的缓存。一条规划失败不会清除另一条仍有效的结果。
3. “预览无避障”切换到红色路径，同时从当前 MoveIt 场景移除本任务的障碍物；“预览有避障”恢复本任务障碍物并切换到绿色路径。其他程序的场景物体始终保留。切换预览本身不移动机械臂。
4. **执行按钮控制实机，并要求对应路径已经预览。** 两套都预览过后，可点击任一执行按钮；它会恢复对应场景并执行那一套原轨迹，不会在执行时换路线或重新规划。“重播”仅播放当前预览。
5. 起点、场景、模型或运动状态变化会阻止执行并要求重新规划。一次执行尝试消耗两套缓存；下一轮重新规划。
6. “返回单点”在同一个窗口恢复官方 MotionPlanning 的拖拽目标和 Plan/Execute；保留当前场景模式并清除多点缓存。停止后若控制门关闭，第四排右侧切换为“恢复控制”；确认恢复后再重新规划，不自动使能或恢复旧轨迹。

终端仍兼容 `p` 规划两套并预览有避障、`b/v` 切换预览、`e` 执行当前预览；面板的五排按钮使用独立命令。

交互规划使用专用的 `ObstacleControl` / RRTConnect 配置，碰撞边检查参数 `longest_valid_segment_fraction=0.0001`；不修改默认规划器或共享流水线的 TOTG 参数。每段对 MoveIt 通用规划失败、无效轨迹、超时返回码及样条采样碰撞最多尝试 5 次，每次保持同一起点、目标和场景。只有通过复查的轨迹才能预览或执行；取消、场景变化、起点/目标无效等错误直接终止。仍不套用纯虚拟演示的 `--clearance` 扩边。虚拟障碍物的移除不会移除现场实物；两种模式都需要与实际现场相符。

**场景页：可视化编辑 → 应用 → 另存为**：

1. 点击“加载场景”，选择 `config/` 中的 YAML。加载进入草稿状态，不立即修改碰撞场景。
2. 在下拉框选中障碍物，勾选“拖拽编辑”，在三维视图使用 **Interact/交互工具**拖动障碍物周围的轴箭头或旋转圆环（不是直接拖绿色碰撞物体，也不是机械臂末端的圆环）；松开鼠标后写入草稿。应用前旧碰撞物体仍在原位置。
3. 也可输入 XYZ（米）、RPY（度）和尺寸，然后点击“写入草稿”。支持箱体、球体和圆柱。“新增”准备新物体的表单，点击“写入草稿”后才加入列表；已有物体名称固定，新增名称必须唯一。
4. 点击“应用场景”：同步到 MoveIt，并关闭拖拽手柄。应用场景会恢复有障碍物模式，旧的两套预览全部作废。
5. 点击“另存为”，例如保存到 `config/scene_custom.yaml`。保存实际采用当前已应用的完整场景草稿；必须使用新文件名，不覆盖原文件。它保存的是本任务管理的几何物体，不是 RViz 窗口布局，也不导出其他程序的障碍物。
6. 返回“运动”页重新规划，即可预览或执行新场景下的路径。

勾选编辑后若没有障碍物手柄，参见[面板连接排查](../multi_point/rviz_panel/README.md#勾选拖拽编辑却没有手柄)。

编辑中的草稿不允许多点规划或执行；任务处理中不接受场景编辑。新加载/新增/删除/拖动/应用操作均清除旧的执行确认。未另存的已应用场景会保留在当前会话，点位重新规划不会用旧磁盘文件覆盖它；退出后需要从另存的文件加载。

每段 `NNN_inspection.json` 保存各次尝试的 MoveIt 错误或采样复查结果，包括碰撞时间、关节位置及接触物体（服务有返回时）。`99999` 本身只是通用失败码；例如时间参数化后的路径可能被官方 `ValidateSolution` 拒绝，应结合 `official_stack.log` 判断。最多 5 次仍失败时，该次规划不可执行，不保证任意场景都可达。

控制会话日志在 `outputs/tasks/obstacle_avoidance/control/`，各轮 `preview_mode.json` 标记有/无避障模式；执行日志引用对应的预览目录。实机到位、停止和恢复约束见[多点任务说明](../multi_point/README.md)。

## 实测起点越界

若运动页显示“起点越界 · joint2 -2.60°”，表示真实反馈约为 `-0.045361 rad`，小于当前模型的 joint2 下限 `0 rad`。这是生成轨迹前的起点检查失败，与障碍物编辑无关。任务不会将反馈截成 0°、扩大限位、自动使能或生成可执行预览。

未使能时的自然下垂可能造成这一情况；未使能本身并不禁止预览，使能本身也不保证姿态回到模型范围。先按机械臂正常操作流程恢复有效姿态，再点击规划；若反馈与实际姿态不符，需核对零位和模型。不能通过反复规划或修改场景消除越界。

面板只显示一行状态，完整错误可悬停查看，并保留在终端与日志。每轮 `initial_feedback.json` 记录未经修改的六关节反馈、时间戳和模型限位；`result.json` 的 `error_details` 列出全部越界关节。失败后仍可编辑场景或返回单点，但不会绕过官方规划器对起点的检查。

## 纯虚拟对比预览

在项目根目录运行：

```bash
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py
```

不加 `--interactive` 的纯虚拟模式使用独立 ROS 域 87，只启动禁用执行功能的 MoveIt、模型发布器和 RViz，不连接 CAN、不启动实机驱动。实体模型显示虚拟起点 A，不代表实机位置。

启动后自动完成：移除本任务障碍物 → 按点序规划三段基准路径 → 加入全部障碍物 → 检查每段基准碰撞 → 扩大障碍物留边并逐段规划绕行 → 在原始场景中逐段复查 → 播放整条绿色轨迹。各段都从上一段的**实际规划终点**接续，不重置到名义目标，不瞬移回 A。

这里的“连续”指各段位置接续并连续回放；每段独立时间参数化，在中间目标处可能减速至停止，不保证以非零速度平滑穿过所有点。演示配置的停留时间为零；对比动画不增加 `hold_seconds` 停留。

| RViz 显示      | 含义                                        |
| -------------- | ------------------------------------------- |
| 原色实体机械臂 | 第一个配置点的虚拟姿态                      |
| 原色透明机械臂 | 当前选择的整条规划轨迹回放                  |
| 橙色半透明箱体 | 参与 MoveIt 碰撞检测的障碍物                |
| 绿色线         | 有避障规划的 TCP 路径                       |
| 红色线         | 无避障基准的 TCP 路径；加回障碍物后存在碰撞 |
| A / B / C / D  | 所有配置目标的 TCP 位置及名称               |

## 终端操作

| 命令           | 操作                                       |
| -------------- | ------------------------------------------ |
| `r`          | 重读点位、场景，重新完成整条路径的对比规划 |
| `b`          | 播放红色无避障基准                         |
| `v` 或 Enter | 播放绿色避障路径                           |
| `s`          | 重读配置并更新场景，使旧预览作废           |
| `c`          | 清除本任务障碍物和预览                     |
| `q` / Ctrl+C | 退出并清理本次启动的进程                   |

任一段规划失败、目标碰撞、路径接续不一致或绕障轨迹复查碰撞，整轮结果作废，不显示部分成功结果或旧轨迹。规划器拒绝某段时最多重试 5 次，点位、场景、容差不变；超时或取消时退出本轮。终端和日志记录失败段号及点名。

## 配置目录与场景

所有配置集中在 `config/`：

| 点位文件                      | 配套场景                     | 用途                        |
| ----------------------------- | ---------------------------- | --------------------------- |
| `config/config.yaml`        | `config/scene.yaml`        | 默认四点、三箱体连续避障    |
| `config/config_simple.yaml` | `config/scene_simple.yaml` | 保留原 A/B 两点、单箱体演示 |

使用原简单场景：

```bash
bash scripts/piperl/run.sh python scripts/task/obstacle_avoidance/run.py \
  --config scripts/task/obstacle_avoidance/config/config_simple.yaml \
  --scene scripts/task/obstacle_avoidance/config/scene_simple.yaml
```

- 点位至少两个，均为 `type: joint`，`joints_rad` 按 joint1～joint6 排列，单位 rad；按列表顺序访问，支持自定义名称。
- 默认四点的 joint1 依次为 `-1.5, -0.5, 0.5, 1.5`，其余关节为 `[1, -1, 0, 0.5, 0]`。
- 三个箱体尺寸均为 `[0.07, 0.07, 0.18]` m，中心分别约为 `[0.130, -0.202, 0.44]`、`[0.24, 0, 0.44]`、`[0.130, 0.202, 0.44]`，随所在方位旋转。它们依次阻挡三段基准扫掠路径。
- 障碍物支持 box `[长,宽,高]`、sphere `[半径]`、cylinder `[高度,半径]`，位置单位 m，坐标系须与配置一致，默认 `base_link`。
- 默认规划时各侧增加 0.025 m 留边；最终显示、碰撞复查使用原始障碍物。可用 `--clearance 0.03` 调整。
- 默认复杂场景每次调用的 `planning_attempts: 1`、`planning_time: 15.0`；任务层保留最多 5 次拒绝重试，避免十次内部尝试导致多障碍物请求过慢。
- 独立规划器使用 TOTG 路径偏移容差 0.0001 rad、重采样间隔 0.05 s，OMPL 的 `longest_valid_segment_fraction` 为 0.0001。不修改实机规划器设置。

所有中间点及首尾点在原始场景和留边场景中都必须无碰撞；整条基准至少一段被挡住才算对比成立。默认配置已验证三段分别被三个箱体挡住，自定义配置不要求每一段都碰撞。若目标点碰撞，应调整点位或场景；若仅留边后碰撞，可检查留边大小。

预览仅管理 `obstacle_avoidance/` 前缀物体，清除时保留其他物体。场景变更必须重新规划；不做动态避障。

### 选择物体与草稿操作

开启“拖拽编辑”后，只在当前选中物体上显示三轴箭头和旋转圆环。可通过左侧物体下拉框选择，也可使用 RViz 顶部 Interact 点击三维物体本体切换选择；表单同步显示所选物体的位置、形状和尺寸。其他物体仍可点击，但不显示操作手柄。单纯选择不会改动草稿、碰撞场景或已有路径。

| 操作           | 更新内容                                      | 是否用于碰撞检测 | 是否写入文件 |
| -------------- | --------------------------------------------- | ---------------- | ------------ |
| 编辑表单数值   | 仅当前表单                                    | 否               | 否           |
| 写入草稿       | 把表单数值写入本次会话草稿                    | 否               | 否           |
| 拖动手柄后松开 | 自动把新位姿写入草稿，无须再点写入草稿        | 否               | 否           |
| 应用场景       | 将整份草稿同步至 MoveIt，关闭手柄、作废旧预览 | 是               | 否           |
| 另存为         | 保存已应用的场景为新 YAML                     | 不改变当前场景   | 是           |

数值编辑后需先“写入草稿”，再“应用场景”；直接点击应用不会读取尚未写入草稿的表单值。想下次继续使用，应在应用后另存为。

### 预览遇到反馈短暂中断

预览获取起点时，会在原有最长 5 秒等待窗口内等待新鲜反馈，并在中断后重新累计停稳时间。仍要求数据年龄不超过 `feedback_timeout`（默认 0.5 秒），不使用旧样本替代真实起点。持续中断会显示“反馈中断 · 检查连接”，`result.json.error_details` 记录源数据年龄、接收间隔、最后时间戳及错误类别。时间戳超前、格式异常和实机执行阶段仍立即中止；恢复通信后需重新规划，不自动恢复执行。驱动的“连接未就绪”不等同于已证明物理线缆断开，应结合 CAN 状态和源时间戳排查。
