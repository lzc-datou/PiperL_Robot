# RViz 六轴伺服与单点控制

[软件验证记录](VALIDATION.md) · [算法公式与输入输出](../../../docs/Servo控制接口.md) · [独立控制参数](config/control.yaml)

在 RViz 拖动 TCP 目标的箭头和圆环，分别控制 XYZ 和姿态。独立笛卡尔控制器输出 TCP 速度，阻尼最小二乘（DLS）将其转换为有界关节速度，再交给官方 MoveIt Servo 的 `JOINT_JOG` 输入。Servo 生成连续关节轨迹，官方 JointTrajectoryController 执行，独立看门狗检查并转发官方驱动接口。任务不直接发送 CAN、不自行插值关节轨迹、不自动使能实机。

## 启动与模式切换

使用手柄时，见 [手柄控制工具](../../tools/gamepad_control/README.md)。手柄在同一窗口提供单轴/笛卡尔两种控制模式，边界采用整体限速并保留反向退回；下文是鼠标目标控制，不是手柄速度模式。

在项目根目录执行：

```bash
bash scripts/piperl/build.sh

# 默认纯仿真，不启动 SDK/CAN 驱动
bash scripts/piperl/run.sh python scripts/task/servo_tracking/run.py --mode sim

# 实机：先结束旧控制栈，在控制面板完成 CAN 连接和使能确认
bash scripts/piperl/run.sh python scripts/task/servo_tracking/run.py --mode real
```

省略 `--mode` 等同 `--mode sim`。面板顶部显示实际模式。实机/仿真切换时先停止、确认停稳、退出任务，再用另一种模式重新启动；不支持运行中热切换。面板的“控制”下拉用于在当前实机或仿真内切换“伺服 / 单点”，无需退出任务；切换会先停止当前动作并取消旧计划。

纯仿真使用官方 `mock_components/GenericSystem`，用于运动学、交互和控制流程调试，不模拟重力、接触或实际电机动力学。实机模式下 RViz、Servo 和位姿误差控制器都使用 `/piper_servo/feedback/joint_states`。模拟控制器状态仅用于采样发送指令，不能作为实机到位证据。

本任务为 Piper-L 无末端模型，TCP 偏置由 `config/config.yaml` 的 `tcp_offset` 统一传给模型和驱动。默认零偏置；装有工具时应填写真实工具偏置并重新启动。实机不继承仿真目标或仿真初始关节角。

实机启动前，先在 [控制面板](../../tools/control_panel/README.md) 完成 CAN 连接和六轴使能确认，再启动上述 real 入口。回零不是前置步骤。运动会话中面板只保留作阻尼急停，不回零或重置；急停恢复先结束旧会话和驱动，经面板重置、使能后重启。

任务启动在独立命名空间 `/piper_servo`；不复用旧驱动或旧 RViz。实机启动入口检查已有官方驱动进程（包括其他 ROS Domain），发现冲突就拒绝启动，不会终止用户已有进程。ROS Domain 和命名空间本身不隔离物理 CAN；不要另开其他 SDK/CAN 控制程序。请使用 `run.py`，不要绕过预检直接启动 launch。

## 面板操作

RViz 新窗口先使用 1100 × 680，再首次适配系统主屏可用区域。窗口菜单提供“移到主屏幕”和“适应当前屏幕”，后续拖动不会自动拉回。另存布局后保留操作者的窗口位置；更新插件需结束当前任务并重新打开 RViz。主屏由桌面显示器设置指定。

| 控件                 | 行为                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| 控制：伺服 / 单点    | 切换时先停止当前动作、取消旧计划，保留目标；不自动使能                                           |
| 开启跟踪             | 保留目标；完整验证后同步真实反馈，再开启连续六轴跟踪；不按条件数自动运动到准备位                 |
| 规划（单点）         | 从新鲜实测关节规划到黄色虚影关节解，检查碰撞、限位、速度和加速度；只规划，不运动                 |
| 执行（单点）         | 执行本次有效计划；修改目标、速度、切模式、停止或反馈起点变化后必须重规划                         |
| 中心球 / 箭头 / 圆环 | 左键直接拖球在视平面内平移，无需辅助按键；箭头沿基坐标系 XYZ 平移，圆环绕基坐标轴旋转            |
| 松开鼠标             | 继续到达最后一个通过检查的目标并保持，保留跟踪开启状态；可接着拖动                               |
| 停止                 | 清除运动许可，覆盖剩余控制器轨迹；实机关闭控制门并请求官方保持服务                               |
| 重置目标             | 先停止，再把屏幕目标对齐新鲜实测末端；反馈超限也能重置显示并提示，不打开控制门、不运动、不标零   |
| 机械臂回零（重置旁） | 显式停止旧任务，再通过官方关节规划运动到六轴零位；完成后对齐实测目标、保持跟踪关闭，不执行零标定 |
| 速度                 | 10%–100%，相对于配置中的 TCP 上限；默认 50%，下方直接显示 mm/s 和 °/s                          |
| 显示可达范围         | 显示/隐藏透明绿色边界曲面                                                                        |

伺服开启后等待准备完成即可拖动。正常松手不结束会话；**松手立即关闭目标速度前馈**，反馈控制继续到达最后的有效目标。到位稳定后进入“已到位 · 保持目标”，暂停滚动轨迹并关闭实机转发门；新拖动的完整目标通过检查后自动恢复，无需重复开启。目标不可达、IK 超时或验证更新超时时撤销旧目标、保持机械臂，但保留会话；继续调整到有效目标即可。点击“停止”、重置、保持失败或真实故障会撤销会话。

目标球可直接拾取；绿色表示完整位姿逆解通过，黄色表示检查中，红色表示拒绝。球的颜色在松手后更新，避免重建控件打断拖动；检查中的新目标不会放行。姿态用四元数/旋转向量计算，避免欧拉角跨 ±180° 时跳变。

面板沿用 RViz 的原生 Qt 配色和控件。标题、两行状态和全宽停止集中固定在顶部；下方连续排列控制方式、动作、速度、误差和折叠诊断，正文可滚动。各项保持自然高度，全屏时余量留在所有内容之后，不拉开提示和按钮的距离。速度比例与上限、位置与姿态误差分别换行；原生停止按钮使用深红文字，滚动或展开诊断后仍在顶部可见。完整原因可通过状态悬停、点击或键盘 Enter 查看；模型图例和可达范围开关位于“显示与诊断”。软件停止不代替物理急停。

字号按面板自身的逻辑像素尺寸调整：紧凑侧栏正文 22 px、按钮 24 px、标题 28 px；宽至少 460 且高至少 850 时为 26 / 28 / 34 px；宽至少 560 且高至少 1200 时为 28 / 30 / 36 px。按钮最小高度随之为 52 / 64 / 72 px，停止再增加 8 px。操作者仍可自由调整侧栏宽度。

黄色半透明模型表示目标机械臂，原色不透明模型表示实际反馈。拖动目标 TCP 的平移控件或姿态圆环时，整条黄色目标机械臂根据同一目标的 IK 解更新；实体机械臂在开启跟踪后按实际反馈跟随。与多点任务的目标编辑显示一致，虚影不是轨迹回放，也不代表实机已经到位。

目标虚影使用官方 MoveIt RobotState 显示和独立 `target_robot_state` 可视化话题；不发布目标 TF，不把预览关节解送入控制话题。虚影不可拾取遮挡末端控件。目标不可达时隐藏无法成立的虚影，保留三维目标位置并提示原因，只有操作者点击“重置目标”才对齐实际末端。

面板将差值分开显示：**位置误差**是目标 TCP 与实际 TCP 的直线距离（mm）；**姿态误差**是两者完整三维朝向的最短旋转角（°），不是某个关节的角度。只拖动球或平移箭头时目标朝向保持不变，所以姿态误差为 0 是正常的；拖旋转圆环可看到角度变化。角度保留两位小数，小于 0.01° 的非零值显示 `<0.01°`；反馈不可用时显示 `—`。

默认只显示本任务操作面板，显示设置可从 RViz 的 Panels 菜单添加。单点、关节调整与回零调用官方 MoveIt 规划服务，由独立看门狗持有官方 JointTrajectoryController 的 action 执行；MoveGroup 自身轨迹执行仍关闭。同一时刻只允许一种控制方式；其他 action 或轨迹来源会撤销控制。所有 TF、轨迹和反馈均使用专用话题。

单点模式的路径在关节空间规划，不保证 TCP 直线运动。黄色模型表示终点位姿；“规划”不会让实体移动，“执行”才放行。计划最多等待 30 s；执行前再次核对新鲜反馈和起点（每关节偏差不超过 0.005 rad）。模拟控制器报告成功后，还必须等真实反馈到目标、连续稳定 0.3 s 并确认关门/保持，才显示“单点已到达”。

## 绿色范围与不可达目标

绿色范围由当前 URDF、TCP 偏置及六个关节限位计算：262144 个固定种子的 Sobol 关节样本 → FK → 4 cm 占据网格 → 高斯平滑 → Marching Cubes 提取边界。RViz 只接收一个透明绿色三角曲面，不渲染内部网格或体素。专用 WorkspaceDisplay 在鼠标拾取时跳过曲面，避免挡住里面的目标球和姿态圆环；自定义 RViz 配置也应使用此显示类型。曲面仅在启动时计算，显示开关只发布已有结果，不在控制循环里重建。最多 20000 个三角形；过密配置会自动调粗重建间距，实际数量和间距写入启动日志。

此方法不使用凸包，能保留采样覆盖到的较大凹陷和内部空洞，但平滑可能消除较小孔洞、收缩或扩张边界。它是**跨不同末端姿态的位置工作空间近似**，不是精确可达集合，不包含环境碰撞排除，也不代表当前位置能连续安全运动到区域内任意点；4 cm 是重建间距，不是误差保证。

展示参考 ABB RobotStudio 的 Work Envelope 思路。[ABB 官方说明第 4 页](<https://library.e.abb.com/public/90644777b379bf46c1257643004f27ef/Whats%20New%20RobotStudio%205-12-02.pdf>) 描述了关节 2/3 扫描形成的 TCP 外侧轨迹，并随第一连杆运动。这里采用适配本机 URDF/TCP 的六关节采样三维边界曲面，没有声称复现 ABB 的算法。

每个拖动目标另行调用 MoveIt 碰撞感知 IK，验证完整 XYZ+姿态、关节限位及 FK 残差。控制只使用已验证快照；持续拖动时，正在计算的快照不会因后续鼠标事件反复作废。通过的快照只能批准它自己的位姿与原接收时间，不能批准最新未检查目标；随后继续检查最新目标。这避免鼠标约 60 Hz、一次 IK 约 45 ms 时一直等不到“最新 revision”，不意味着取消 IK。旧会话/停止前的结果仍拒绝，过期或失败快照撤销运动。

运行中目标不可达或检查超时：标红、撤销旧目标并保持暂停，跟踪会话保留；继续拖动产生新目标、完整验证通过后恢复，无需重复开启。只回到绿色区域不等于完整位姿有效，仍需通过 IK。未开启时的无效目标仍不能启动；需要对齐实际末端时手动点击“重置目标”。不会自动裁剪目标姿态，也不会强行把目标投到边界。

逆解最多生成六个不同数值种子：合法规划参考、前一次预览解、`ready_joints` 数值参考、关节范围中点及两个腕部翻转猜测；**种子不会直接驱动机械臂**，也不保证覆盖全部分支。实时跟踪优先接受第一个完整合法解以减少等待；未开启跟踪的预览、单点与关节恢复收集候选，按归一化关节移动量和边界余量选解。所有候选仍须通过官方碰撞 IK、硬限位、软余量及 FK 残差检查，不把裁剪种子当作有效逆解。每次服务预算30 ms、客户端超时120 ms不变。

Servo 在运动中继续检查碰撞、关节速度/加速度和软边界；当前 `JOINT_JOG` 路径不使用原笛卡尔条件数减速/停机。IK 成功不保证从当前状态沿局部伺服路径可达。DLS 在奇异附近给出有界近似速度，无法实现的瞬时方向可能变慢或停滞；它不做全局绕障。环境障碍物必须进入 `/piper_servo/planning_scene`；仅在 RViz 显示物体没有避碰作用。默认未建模现场桌面或周围物体。

## 原生暂停、停滞恢复与回零

面板“目标可达”表示完整位姿存在合法逆解；当前位置能否沿局部伺服路径到达，还取决于当前关节分支。旋转后腕轴接近边界时，继续保持朝向平移可能触发原生限位。当前以正阻尼 DLS 输出有界 `JointJog`，不再按 κ=17/30 拒绝启动、恢复或减速。官方碰撞检测、关节速度/加速度与软限位仍生效，硬限位未扩大。

运行中的关节调整流程为：

1. 原生关节边界暂停，或松手后连续 **1.5 s** 综合 TCP 误差未下降 1%、关节最大变化小于 **0.003 rad** 时，先保持并关闭运动许可。普通 warning、正在拖动或仍有明显进展不会单独触发调整。
2. 保留同一完整目标和会话，重新做多种子碰撞感知 IK，综合比较关节移动量和边界余量。使用种子本身不会移动机械臂。
3. 鼠标松开、目标稳定 **0.15 s**、当前 revision 通过完整验证且旧动作已终止/控制门关闭后，调用官方 MoveIt 关节规划到该目标；每个 revision 最多调整一次。无可行解时保持并提示，继续调整目标即可。
4. 规划执行完成后显示“已到位 · 保持目标”，保留会话并保持控制门关闭；不会自动回准备位，也不会重启旧伺服命令。下一有效新目标重新同步后恢复 Servo。

关节调整排队或执行期间继续拖动，会撤销旧计划/动作并闭门，保留会话和最新目标；等待旧动作终态确认、松手和新目标验证后，再规划最新目标，不并发执行。**单点、回零动作中编辑目标仍会停止相应动作**；它们不沿用上述连续恢复行为。调整走关节路径，不保证 TCP 直线运动。`ready_joints` 默认 `[0,1.40,-1.20,0.30,1.00,0]` rad，只作数值 IK 参考；不再由条件数自动执行准备动作。

取消调整时仅撤销执行许可，Guard 保留自己发出的 action UUID 身份，避免延迟的“执行中/取消中”状态被误判成其他轨迹任务。旧动作确认成功、取消或中止后释放交接等待；先到达的终态不会被晚到达的接受响应重新改为未结束。`guard/status` 的 `pending_joint_actions` 表示尚未确认终态的本任务动作数量，`other_action_active` 单独表示未知来源的活动轨迹；真正的其他轨迹仍会阻止开启跟踪。

“回零”是另一次明确的运动请求：停止旧会话，再按官方关节路径到 `[0,0,0,0,0,0]`。零目标按硬限位检查，不因软余量或奇异性被排除；整条路径仍检查碰撞、速度、加速度和真实反馈。完成后目标对齐实测 FK、跟踪关闭，需要时重新开启。**它不是零点标定。**

当前模型零位的 J4/J6 轴线基本重合，雅可比秩为 5；零位显示奇异并不证明标定有误。重置目标只显示原始实测 FK，不能改变真实反馈。`zero_feedback_tolerance` 最大 0.1°，仅容许 real 模式 J2 下零/J3 上零的微偏读取；规划参考可将这两项规范到边界，原始反馈不改，目标/轨迹/转发命令保持严格硬限位。其他越界仍阻断运动。

正常 Servo 开启/恢复使用 pause → 控制器对齐真实反馈并稳定 → unpause 清空滚动窗口 → 确认后开门。关节调整及回零共用官方规划、Action 身份和停止屏障；停止、反馈/电机异常、碰撞或控制权冲突仍撤销许可。

## 实机停止与反馈

- `guard.py` 是独立进程：短 Servo 轨迹与长单点计划分别验证，不扩大 Servo 的 0.3 s 窗口。单点计划检查完整 p/v/a、起终点、时间与所有采样点，以及 JTC 五次多项式段之间的位置/速度/加速度极值；计算在独立工作线程完成，反馈与停止处理不会等待这项计算。原轨迹不改写，MoveIt 时间参数化、官方 JTC 负责插值。官方规划请求默认使用面板比例的 80% 速度、25% 加速度，给控制器插值峰值留余量；仅当完整验证发现速度/加速度超限时，最多降低参数重新规划两次，验证阈值始终不变。实机指令继续检查位置范围与指令变化速率；不再以指令角和实测角的距离中断跟踪。
- 真机使能和电机/机械臂诊断必须正常；陈旧时间戳的重复反馈不能刷新有效期。模型及命令位置限位不变；除上述 J2/J3 零边界的有限读取容差外，现场负角度或零位不一致仍需先核对模型、零位约定和真实姿态。
- 示教、轨迹回放及其他外部控制模式拒绝开启。官方控制门或停止/保持服务未确认时拒绝恢复，不绕过驱动的拒绝结果。
- 开启时实机控制门保持关闭，模拟控制器先对齐真实反馈，并确认稳定后才允许转发。停止时覆盖旧轨迹、禁止转发并关闭驱动控制门；恢复不继续旧动作。
- 后端失联由独立看门狗停止；RViz 面板心跳中断、拖动事件超时、Servo 输出/状态中断、反馈超时或过大误差均撤销许可。启动器还监测后端和看门狗心跳。
- 官方 `/emergency_stop` 的当前实现是向当前测得的关节位置发保持请求；名字不代表硬件级急停。服务返回也不是机械臂物理停稳证明。系统不是安全认证控制器，实机首次使用需要现场低速验证停止距离、响应与固件行为，保留可用的物理急停。
- 默认改为与多点任务一致的官方 `fast_mode=false → move_j`，保留原 Servo/JTC 平滑与限速。此前的 `move_js` 无 SDK 内部平滑/轨迹规划，反馈闭环行为与普通关节接口不同；旧自定义配置仍可选择，但不能据纯仿真结果判断实机效果。本次没有热切换或驱动实机。

当前默认 TCP 最大平移速度 **0.30 m/s**、角速度 **1.50 rad/s**；面板 50% 时为 **150 mm/s、42.97°/s**，100% 时为 **300 mm/s、85.94°/s**。在 `config/control.yaml` 分别调整 `linear_speed`、`angular_speed`，面板按当前比例显示对应上限。显示值不是实时反馈速度；接近目标、奇异区或触及加速度限制时会降低。

任务关节标称软件速度上限为 **2.40 rad/s**（约 137.51°/s），各轴仍受下方官方最高速度限制；加速度维持 **1.50 rad/s²**，不根据速度表推导或提高加速度。它们是任务软件参数，不是固件标称值。[PiPER-L 官方用户手册 V1.1.0 的 1.2 节](https://agilexsupport.yuque.com/staff-hso6mo/alxgtf/fvtsoyfpewxeuy5v?singleDoc)给出各轴最高速度：

| 轴           | 官方最高速度 |   rad/s |
| ------------ | -----------: | ------: |
| J1 / J3      |      180°/s | 3.14159 |
| J2           |      195°/s | 3.40339 |
| J4 / J5 / J6 |      225°/s | 3.92699 |

`joint_velocity_limits` 保存上述各轴上限，不能配置为超过官方值；实际软件关节基准上限按每轴 `min(joint_speed, joint_velocity_limits[i])` 计算，当前 J1–J6 均为 **2.40 rad/s**。面板比例同时缩放 TCP 上限和 DLS 关节速度上限，默认 50% 时 DLS 每轴不超过 **1.20 rad/s**；官方 Servo/JTC 和转发处仍独立检查模型/配置上限。单点/关节调整/回零规划也乘面板比例及规划余量：默认 50% 的轨迹检查速度上限为每轴 **1.20 rad/s**，初次规划请求为 **0.96 rad/s**，加速度余量不变。短动作可能由加速度限制决定耗时，未必达到速度上限。没有写入或修改固件速度、加速度参数。Servo 周期 100 Hz、控制器/反馈 200 Hz 不变。

到位保持默认条件为：松开鼠标、完整目标已通过检查，TCP 在 **3 mm / 0.02 rad（约 1.15°）** 内，关节变化不超过 **0.003 rad** 并持续 **0.30 s**。随后暂停 Servo、覆盖控制器轨迹，实机关闭门并调用官方保持；会话保留，反馈噪声或旧目标不会自动重开门。新拖动的完整目标验证后才恢复。该保持区参考普通任务的到位判据，用来避免到位后围绕紧容差持续纠偏，不是精度承诺；原 1 mm / 0.01 rad 的 Twist 置零阈值仍保留。

目标与实际末端之间的距离只决定追赶时间，不再使用原来的 12 cm / 0.70 rad 距离退出规则。面板分别显示位置误差和姿态误差；目标通过完整位姿 IK 后按既有速度上限逐步跟踪。已删除实机关节命令与反馈相差超过 0.10 rad 的停机分支，不改成新的阈值或持续时间判断。旧 `max_joint_tracking_error` 配置读取时忽略。旧配置中的 `max_position_error`、`max_orientation_error` 已弃用，读取时忽略。配置变体放在 `config/`，通过 `--config 路径` 使用；修改后重启。

## 独立控制算法与参数

随附 [control.yaml](config/control.yaml) 当前选择 `pi`。五种算法、执行反馈抗饱和、松手速度制动、同增益调参和历史软件 benchmark 集中在 [Servo 控制接口](../../../docs/Servo控制接口.md)，本操作页不重复数学与实验数值。手柄后端不使用鼠标目标追赶算法。

算法配置选择顺序为 `--control-config`、任务 YAML 的 `control_config`、相邻 `control.yaml`、模块默认配置。详见 [参数路径](../../../docs/Servo控制接口.md#参数分层与路径优先级)。修改后停止并重启任务，不热加载。

运行和清理日志保存在本机 `outputs/servo_tracking/<时间>_<模式>_d<Domain>_<PID>/`，不随源码克隆分发。任务只回收自己创建的进程组。

## 依赖与验证

ROS 2 Jazzy、现有官方模型/驱动、MoveIt Servo、NumPy、SciPy、scikit-image（系统包 `python3-skimage`）和 interactive_markers。可使用系统 Servo 包，或将锁定的官方 APT 包解包到项目 `.deps/servo`，由项目环境入口加载。来源及校验见 `config/dependency.json`。重建此私有依赖：

```bash
bash scripts/task/servo_tracking/prepare_dependency.sh
bash scripts/piperl/build.sh
```

也可以由操作者安装系统包 `ros-jazzy-moveit-servo`，不使用项目私有副本。配置与依赖修改后重新构建、关闭旧入口再启动。

当前检查范围见 [验证矩阵](VALIDATION.md)，测试和隔离集成入口见 [tests/README.md](../../../tests/README.md)。不要在正常操作会话中运行集成脚本；历史准备位、条件数停机与旧模式测试先核对适用版本，不把旧结果当成当前验收。
