## 3. 固定操作映射

控制参考系固定为 `base_link`，TCP 固定为模型配置的 `tcp_link`。旋转是在 TCP 点产生角速度，不是让 TCP 绕基座原点公转。已有 TCP 偏置必须从模型读取，不硬编码另一个末端点。

| 操作 | 功能 |
| --- | --- |
| 持续按住 LB | 持续运动许可；不是开关，不使用 sticky/toggle 按钮模式 |
| 左摇杆前后 | TCP 沿基座 X 方向移动 |
| 左摇杆左右 | TCP 沿基座 Y 方向移动 |
| 右摇杆上下 | TCP 沿基座 Z 方向升降 |
| 右摇杆左右 | 绕基座 Z 轴转向 |
| 十字键上下 | 绕基座 Y 轴俯仰 |
| 十字键左右 | 绕基座 X 轴侧倾 |
| B | 软件停止并锁定；不依赖 LB 是否按下 |
| A / X / Y / RB / LT / RT / 摇杆按下 / 背键 | 本版不分配运动功能 |

为消除符号歧义，默认逻辑约定：左摇杆前推产生 `vx>0`，右推产生 `vy<0`；右摇杆上推产生 `vz>0`，右推产生 `wz<0`；十字上/下产生 `wy` 正/负，十字左/右产生 `wx` 正/负。软件正向按右手系定义；首次只读输入校准和仿真确认后保存轴符号。固定基座系下，不承诺任意工具姿态时“十字上”都是相对于工具自身的抬头。

### 3.1 输入处理

- 优先使用 ROS 2 `joy/game_controller_node` 的 SDL 标准映射。普通 `joy_node` 仅在标准映射不适用时使用显式设备 profile；不能假定其索引相同。
- 标准映射参考：左 X/Y 为轴 0/1，右 X/Y 为轴 2/3，LB 为按钮 9，B 为按钮 1，十字上/下/左/右为 11/12/13/14。必须核对实际设备、连接模式及轴符号，不能把参考索引当实测结果。
- 每帧验证长度、有限值、取值范围、设备身份、连接代数和输入有效期。无效输入撤销许可，不能沿用最后一次非零命令。
- 摇杆死区后重新映射到完整 `[0,1]` 幅度，曲线连续、单调且过零；小幅输入方便精细操作。可使用径向死区避免斜向中心噪声。
- 三维平移向量和角速度向量分别做范数限幅，防止组合输入超过各自总上限。关节速度由 DLS 与下游独立限制。
- 十字键为低速持续点动，松开停止；相反方向同时出现视为该轴零输入，不依赖按键处理先后顺序。
- 摇杆回中时对应轴命令归零。所有轴回中且 LB 仍按住时，请求零速度；不积累等待以后执行的位移。
- B/断线/松开 LB 的停止优先级高于滤波、限加速度和普通输入处理，不能因滤波长尾继续保持运动许可。
- 不在遥操作层将摇杆速度积分成一个远处目标再用 P/PI/PD 追赶；不得复用鼠标“松手后继续追踪旧目标”的语义。

### 3.2 有线与无线

输入适配后两种连接使用完全相同的逻辑映射。设备 profile 应区分设备标识、SDL GUID（如果可得）与连接模式，重新枚举后不能仅按 `device_id=0` 接受另一只手柄。

`/joy` 的新消息、当前时间戳、自动重发和后端心跳，都不单独证明手柄仍在线。标准驱动可以重复发布缓存状态；接收器仍插在 USB 口也不证明无线手柄仍连接。

实现必须分开记录：

1. 输入进程是否存活、消息是否按时到达。
2. 输入设备是否仍连接、是否属于同一连接代数。
3. 所选连接方式是否具有已验证的手柄失联检测机制。

不要简单把“没有轴变化事件”当断线：操作者可能保持固定偏转。也不要使用“定时给旧值盖新时间戳”解决超时。应核对 SDL/内核设备断开事件和无线接收器实际行为；必要时增加只读链路状态适配。若某模式无法及时可靠识别断线，该模式仍可用于只读检查/仿真，但实机入口必须显示“该连接方式尚未通过失联验证”并禁止运动许可。

重连必须产生新连接代数，清除全部输入历史，等待 LB 松开与摇杆回中，再由操作者显式恢复；旧消息、旧许可、旧异步服务结果均不能跨连接代数恢复运动。

### 4.1 顶部连接与状态区

- 手柄名称、连接方式、连接状态；机械臂是否已使能；真实反馈是否新鲜。
- 醒目显示仿真/实机；运行中不能热切换。默认仿真，实机必须显式选择。
- 自动查找上次选择的已知设备，多设备/失败时才需要用户展开设备选择。
- 没有可靠电量信息时显示未知或不显示，不猜测百分比。
- 状态文案为普通中文，例如“等待手柄”“请松开 LB 并让摇杆回中”“等待机械臂使能”“其他任务正在控制机械臂”。不要只显示错误码。
- 颜色与文字同时表示状态，不能只依赖颜色。

### 4.2 手柄示意与反馈

- 使用 Qt 自绘展示手柄轮廓、两摇杆偏转、十字键、LB/B 高亮；随真实输入刷新。
- 示意图是只读显示，不允许鼠标点图直接驱动机械臂。
- 默认显示实际 TCP XYZ（mm），姿态与关节角（°）折叠；说明旋转表示约定，例如固定 XYZ 的 RPY，并显示坐标系。
- 反馈过期：主读数显示“—”，明确“反馈中断/停稳未知”；不得继续把旧读数当实时值。可在诊断中保留带时间的最后有效值。
- 实机读数来自真实关节反馈与 FK，不能显示目标/控制器指令为“实际”。仿真必须明确标记。
- 第一版不嵌入三维机器人视图；可使用已有 RViz 作观察。不得启动鼠标目标后端来满足 RViz 显示。

### 4.3 速度和两个主按钮

- 只有一个最高速度滑条，建议 5%～100%、步长 5%，初始 20%；同时展示对应平移/旋转上限。100% 是本工具配置上限，不是硬件极限。
- LB 按住、运动准备/停止过程中禁用调速；松开后可调。后端也验证条件，不能只靠控件禁用。
- “开始控制”：准备并取得工具会话，显示“等待按住 LB”，不自动使能、不回零、不产生非零运动。
- “结束控制”：先停止、确认停止结果，再释放会话与控制权。
- “恢复控制”：仅在故障原因已解除、LB 松开、输入回中、反馈正常和停稳确认满足时可用；恢复后仍等待新的 LB 按下。
- 红色“停止 B”位置固定，与 B 键走同一停止入口；不需要确认弹窗。它只停止本工具拥有的执行链，不抢占或取消无关任务。
- 按 LB 前摇杆已偏转：不动，提示回中；不能边偏转边按 LB 直接启动。
- 不保存运动许可；重启或重连不会自动开门。可以保存设备 profile、窗口位置和折叠偏好；重启速度恢复保守默认值。

### 4.4 折叠诊断与窗口生命周期

诊断内容：设备选择、只读校准、原始/归一化轴值、输入健康、连接验证状态、反馈 age、当前控制者、许可、停止是否确认、限位/碰撞原因、最近事件、日志目录。仅非控制状态允许切设备/改映射/校准。

GUI 线程只做绘制与短操作，不执行阻塞 ROS 服务、进程等待或计算。GUI 事件循环提供心跳；后台线程活着不能掩盖窗口已卡死。正常切换焦点去看 RViz 不改变已定义的 LB 操作；关闭窗口必须撤销许可并异步进入停止与清理流程。若反馈丢失，提示“无法确认停稳”，不能用关闭窗口或服务 ACK 替代停稳证据。

## 5. 控制状态机与停止语义

将用户会话、LB 持续许可、guard 执行状态和停稳确认分开建模，不把它们合并成一个 `connected`/`enabled` 布尔值。

| 工具状态 | 进入条件/行为 | 非零输出 |
| --- | --- | --- |
| WAITING | 等设备、模型、反馈、使能或控制权 | 禁止 |
| READY | 基础条件可用，未开始会话 | 禁止 |
| ARMED | 用户开始/恢复成功，等待 LB；已观察到松开与回中 | 禁止 |
| PREPARING | 新 LB 按下，guard 正在暂停、对齐、重置、开门 | 禁止 |
| ACTIVE | 本次许可、输入、反馈均有效，guard 确认 running | 允许有效输入对应的有限速度 |
| STOPPING | 松开 LB/B/退出/故障，已撤销许可，等待停止确认 | 禁止 |
| LOCKED | B/断线/故障后锁存；原因解除仍需显式恢复 | 禁止 |
| STOP_UNKNOWN | 已请求停止但反馈不新鲜或停稳无法确认 | 禁止，禁止自动恢复 |

### 5.1 正常开始与松开 LB

开始/恢复只建立会话。必须见到当前连接代数内的新鲜“LB 松开且所有运动输入回中”状态，随后才接受新的按下沿。新的 LB 许可触发下游准备；只有 guard 确认完成同步后才能转发当前仍有效的输入，不排队重放准备期间的旧命令。

松开 LB 立即撤销运动许可、清空输入滤波/命令历史、使所有旧异步回调失效，并请求现有 guard 的停止/保持流程。用户会话保留；确认停稳、LB 松开且输入回中后回到 ARMED。再次运动要求新的 LB 按下沿。若很快松开再按下，不能越过 STOPPING/同步屏障。

### 5.2 B、失联与异常

B、手柄断开、输入/GUI/后端超时、真实反馈异常、Servo 故障、控制权冲突等都撤销许可并锁存。链路恢复、状态变绿或旧服务成功不能自动解除锁定。恢复必须是用户明确操作，且重新通过当前状态检查。

停止不仅是发布一次零速度：必须结合原有 Servo 暂停、控制器旧轨迹覆盖/清理、驱动控制门关闭、官方保持请求和下游确认。保持不等于断电/失能；不擅自发送 raw CAN 重置或阻尼命令。

服务返回成功仅表示请求受理。界面只有在必要的关闭/保持确认、动作终态（若有）、连续新鲜实测关节稳定性都满足时显示“已停止”。`guard/status.state=idle/holding` 和 `gate_closed=true` 本身也不是物理停稳证明。

停稳观察应使用多个不同源时间戳的真实样本；以短窗内关节最大位移/速度估计等有界条件确认，明确静止阈值与观察窗。连续窗口要求避免慢速累计位移被相邻样本小差值误判。超时显示 STOP_UNKNOWN，不使用固定 sleep 后无条件宣布停止。

窗口退出/后台退出需要保留看门狗与驱动足够时间处理停止；清理仅针对本工具启动的进程组。若 guard 本身死亡，启动器采用既有独立停止兜底，不能立刻杀掉唯一还能完成保持的驱动。

## 6. 实现架构与接口

### 6.1 进程划分

```text
Qt GUI 进程 ← 状态快照 / 请求应答 → gamepad_backend（ROS 2）
                                  ↑
                           输入节点 + 连接健康信息
                                  ↓
                     DLS → MoveIt Servo
                                  ↓
                       独立 servo_guard → JTC → 官方驱动
启动器：持有互斥锁、监督进程、负责异常退出兜底
```

- GUI 不持有 CAN/SDK，不直接发布关节轨迹。
- 后端以固定控制周期处理最新有效输入；不能让 Qt 刷新频率决定运动周期。
- 看门狗必须是独立进程；后端活着但输入过期时也必须失去运动许可。
- 使用小而明确的消息/快照接口。可用本机 IPC 或 ROS 通信，选择现有依赖可支持、易测试的方式；Qt 与 ROS 不能阻塞彼此。
- 标准 ROS 输入可用 `sensor_msgs/Joy`；另外传递设备身份、连接代数和链路健康。不要往 `Joy.header` 中塞进未经证实的“硬件新鲜度”。

### 6.2 数据合同

建议用无 ROS 依赖的数据类定义以下概念，字段名可调整但语义必须保留：

| 类型 | 必要信息 |
| --- | --- |
| InputSnapshot | 设备/profile 身份、连接代数、序号、接收单调时间、可用的源时间、连接/链路健康、四摇杆轴、D-pad、LB、B、校准状态 |
| MotionIntent | 会话代数、输入代数/序号、单调有效期、基座系六维速度、许可状态；不能无限重盖时间戳延长旧输入寿命 |
| ControlRequest | start/stop/end/recover/set_speed/select_device；请求 ID 与会话代数，重复停止幂等 |
| StatusSnapshot | mode、设备、会话状态、guard 状态、控制权、原因、许可、实际位置及源时间、速度上限、停止确认/未知 |

使用单调时钟计算本机超时，ROS 时间用于消息合同；拒绝乱序、过期、未来异常时间和旧代数结果。UI 请求等待时仍可提交更高优先级停止；迟到 start/recover 回调不能重开门。

### 6.3 复用执行链的建议方式

优先为现有 launch 增加可选输入来源/后端选择，默认保持原 RViz 行为。gamepad 模式只启动手柄后端，不能同时启动鼠标后端；复用同一 Servo、guard、JTC、官方驱动配置与生命周期。若独立 ROS 包更清晰，可在本工具目录提供包定义，并更新构建入口；避免复制一整份 guard 形成两套不同安全逻辑。

允许把确实需要共享的无状态功能抽到 `scripts/task/common/`，保留原导入/调用兼容性。不要为本任务进行无关大重构。新增 guard 条件应以显式输入类型参数控制，保持原任务缺省行为并有回归测试。

已存在的 ROS 接口（在 `/piper_servo` 命名空间下）如下，实施时核对类型及状态合同：

| 相对接口 | 类型/用途 |
| --- | --- |
| `servo_node/delta_joint_cmds` | `control_msgs/msg/JointJog`，实际 Servo 输入 |
| `servo_node/switch_command_type` | `moveit_msgs/srv/ServoCommandType`，要求 JOINT_JOG |
| `servo_node/pause_servo` | `std_srvs/srv/SetBool`，暂停/重置 |
| `guard/enable` | `std_srvs/srv/SetBool`，执行门准备/停止，不是硬件使能 |
| `guard/hold` | `std_srvs/srv/Trigger`，现有到位保持语义；不能未经适配假定可在所有状态调用 |
| `backend/heartbeat` | `std_msgs/msg/Float64`，现有后端心跳；不能当成手柄健康 |
| `guard/status` | `std_msgs/msg/String` JSON，执行状态/门状态，不是物理停稳证明 |
| `feedback/joint_states` | 实机真实关节反馈 |
| `commanded_joint_states` | 控制器侧状态，仿真可用于反馈，实机不能替代真实反馈 |
| `control_enable` / `emergency_stop` | 官方驱动门/保持接口，由已有执行链拥有 |

为手柄状态/输入/GUI 心跳增加独立接口，并记录实际名称。不要冒充旧 RViz 面板心跳来绕过原后端检查。独立 guard 应在手柄模式检查输入许可有效期（包括设备代数/失联）、后端心跳和必要 GUI 健康，不能只由后端定时广播“我还活着”掩盖上游故障。

### 6.4 控制与安全边界

- 手柄直接提供速度意图，复用 `damped_joint_velocity()` 后送 `JointJog`。当前 DLS 会给出有界近似速度；奇异附近可能变慢、停滞或方向失真，不能声称消除了奇异。
- 当前 JOINT_JOG 路径没有原笛卡尔条件数减速/停止；不要在文档中声称这项保护已存在。保留实际可用的碰撞、速度/加速度、关节边界与跟踪误差检查。
- 速度模式没有固定目标，不执行鼠标目标的完整位姿追赶和自动关节调整。保留新鲜实际状态、轨迹有效性、软硬限位及碰撞检查；不要为凑“目标校验”虚构远处位姿。
- 保持 `check_collisions=true` 与现有 scene 接入；只有进入执行栈 PlanningScene 的物体才参与检查。RViz 中可见不等于参与避碰；无感知、无自动全局绕障能力。
- 工具速度配置不能照抄当前伺服任务的较高默认值，也不能把通用模型 `5 rad/s` 当实机能力。关节上限取本工具、现有模型及已确认设备限制的最小约束，不写固件。
- 不扩大 J2/J3 零边界读取容差，不更改原始反馈，不裁剪越界指令为看似合法结果，不绕过故障 gate。
- 互斥必须覆盖同一物理 CAN，不只依赖 ROS namespace/domain。已存在驱动/任务时拒绝接管并说明原因；不强杀别人的任务。输入来源和 JTC/driver 发布者必须唯一。

以下是**供离线/仿真起步的拟定软件默认值**，不代表已验证的实机安全速度或响应时间。实施者可以根据集成验证收紧，不得为通过测试放宽现有边界。最终有效参数及变更理由写入验证记录。

| 字段 | 初始建议 | 含义 |

| `input_repeat_hz` | 50 | 上层状态重复发布，与硬件链路健康分开 |
| `deadzone` | 0.08 | 归一化摇杆死区，按设备校准 |
| `neutral_dwell_s` | 0.15 | 松开 LB 且回中持续窗口 |
| `response_exponent` | 1.5 | 死区重映射后的灵敏度曲线 |
| `linear_speed_max` | 0.05 m/s | 工具平移向量上限 |
| `angular_speed_max` | 0.25 rad/s | 工具角速度向量上限 |

| `command_timeout` | 不宽于现有 0.20 s | Servo 输入期限 |
| `settle_window_s` | 0.30 | 停稳观察窗，阈值与测量算法需验证 |
| `settle_joint_span_rad` | 0.003 | 整个观察窗内关节范围的初始判据 |

所有数值必须有限、量纲明确、范围有效；NaN、负速度、越界比例等应启动失败并给出可读原因。配置文件由工具拥有，不修改现有鼠标 Servo 的默认速度。配置变更不能在 ACTIVE 状态偷偷生效。

建议入口合同（实现后 README 给出在项目环境内可运行的完整命令，不把此处视为已经可运行）：

```text
run.py --mode demo     # 无 ROS/设备依赖的界面演示，始终标记示例
run.py --mode input    # 只读手柄输入和链路检查，不启动机械臂执行栈
run.py --mode sim      # 默认；官方 mock 硬件，与实机隔离
run.py --mode real     # 显式选择；保留人工使能与全部控制门
```

允许离线/仿真输入 fixture 以完成无人手柄验证，但 `real` 模式必须从结构上拒绝注入输入、假反馈与 demo 状态。仿真不能因为发现 CAN 就自动切实机。启动脚本路径统一使用项目环境包装，不要求用户手动修复 Python 路径。

## 9. 验收要求

### 9.1 自动化与离线

| 类别 | 必须验证的行为 |
| --- | --- |
| 固定映射 | 四摇杆轴、十字四方向的符号/单位正确；无模式切换；未分配按钮无运动作用 |
| 死区与组合 | 中心噪声不动，边界连续；斜向输入不超平移/角速度范数；数字相反方向冲突归零 |
| 非法输入 | 长度不对、NaN/Inf、乱序、错误身份、旧连接代数均拒绝；不能复用旧非零速度 |
| LB | 按住之前必须松开且回中；松开撤销许可；快速重按不能越过停止和准备屏障 |
| B | 无需 LB，优先停止、锁存；链路恢复或状态变绿不能自动恢复 |
| 异步竞态 | 停止后迟到的开始/恢复服务结果不会开门；切设备、重连、旧消息不串会话 |
| 新鲜度 | 重复源时间戳不刷新真实反馈有效期；Joy 自动重发不能冒充无线在线证据 |
| 停稳 | ACK、gate_closed、固定定时器均不能独立宣布停稳；反馈缺失显示未知；慢漂移不误判静止 |
| GUI | 开始/结束/恢复文字与可用性正确；输入图更新；过期数据显示“—”；速度运动中锁定且后端拒绝绕过 |
| GUI 生命周期 | 卡死/心跳停、关闭窗口、后端崩溃进入停止；UI 操作不被服务等待阻塞 |
| 隔离 | demo/input/sim 不创建真实 SDK/CAN 执行；real 禁止 fixture；其他控制者存在时不强行接管 |

纯逻辑测试注入时钟，避免依赖长 sleep。Qt 用项目已有 offscreen/QtTest 测真实交互和布局可用性；不以按钮数量等无行为断言替代操作验收。

### 9.2 纯仿真集成

- 使用现有官方 mock/JTC，真实启动 Servo 与独立 guard，不以全部 mock 掉执行链的单元测试代替集成。
- 六个自由度逐个给低速输入，检查 FK 的方向/量级；DLS 近奇异时允许近似误差但必须有界并说明，不能使用任意大容差掩盖符号错误。
- 持续输入后松 LB、按 B、关闭 GUI、停止输入进程、停止后端进程，分别验证旧指令不再转发、重启不自动运动。
- 注入连接代数改变、输入重放、源时间戳冻结、Servo 输出中断和停止中恢复请求，验证状态机与实际输出一致。
- 验证碰撞/关节限位与共享 guard 的约束仍有效，不能关掉检测才能完成演示。
- 运行相关 `test_servo_damped_velocity`、`test_servo_controller_sync`、`test_servo_hold_guard`、`test_servo_guard_recovery`、反馈/轨迹边界测试，具体按最终修改范围选择。
- 拍摄实际 Qt 界面（正常、停止锁定、输入/反馈故障），检查主操作不被截断；不要用网页草图截图冒充已实现窗口。

### 9.3 手柄与实机验收，留待用户安排

手柄侧应记录实际设备名/标识、连接方式、驱动版本、按键与轴值、回中噪声，以及拔线、手柄关机、接收器保留时断链、重连的观测结果和检测耗时。未接入手柄时不要声称已经通过硬件兼容验证。

实机侧另行确认当前使能/模式、反馈、活动空间、负载/支撑、物理停止手段；从最低档开始测真实停止响应与距离、稳定性、重连不恢复、控制冲突。上述拟定超时不是已经测得的物理停机时间。开发对话不能自行开展这些运动测试。

## 10. 交付与完成判定

交付至少包括可运行的 Qt 界面、真实输入适配代码、专用后端和共享执行链适配、配置、测试、运行文档和 `VALIDATION.md`。不能只交一个漂亮 demo 或仅发布 `/joy` 的桥接脚本就称工具开发完成。
