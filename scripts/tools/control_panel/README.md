# PiPER-L CAN 控制面板

默认 640 × 560，可调整窗口大小；按钮高度至少 100 px、文字 24 px，状态文字 18 px。提供端口选择和五个按钮，直接收发底层 CAN 帧，无 ROS、SDK 或监控面板。使能与回零只在按钮执行期间读取必要的控制器状态。

## 使用

在项目根目录运行（Python-only，不加载 ROS 环境）：

```bash
bash scripts/piperl/run.sh --python-only python scripts/tools/control_panel/run.py
# 离线查看界面和按钮流程，不打开 CAN
bash scripts/piperl/run.sh --python-only python scripts/tools/control_panel/run.py --demo
```

也可直接使用安装了 PyQt5 的系统 Python：

```bash
/usr/bin/python3 scripts/tools/control_panel/run.py
```

依赖 Linux SocketCAN、iproute2、Python 3、PyQt5；手动激活接口需要系统图形授权工具 pkexec。速率固定为 1 Mbps。

## 端口选择与自动接入

- 启动后自动扫描系统 CAN 口，之后每秒刷新；下拉框显示端口名、UP/DOWN、速率及异常状态。这里只检查网络接口，不订阅机械臂反馈。
- 只有一个端口且没有历史选择时，自动选中。存在多个端口时，优先使用上次明确选择的端口；没有记录时等待用户选择，不默认选第一个。首次检测到多个端口后，即使只剩一个也继续等待选择。
- 所选端口 UP、1 Mbps、ERROR-ACTIVE 时自动打开仅发送的 socket，显示“CAN 已连接”，无需点击连接。自动接入不发送控制帧、不使能、不回零。
- 所选端口 DOWN 时才可点击“CAN 连接”，授权配置速率并启用接口。已 UP 但速率错误、BUS-OFF 或其他异常时提示错误，不自动关闭或重配。
- 上次选择的端口不存在时保留该选择并提示，不切到其他端口。选择记录保存在当前用户的 Qt 设置 `PiperL/RawCanPanel` 中；演示模式不读写此记录，不依赖 ROS 驱动配置。
- 切换端口会关闭本面板的旧 socket，取消尚未发送的旧操作，包括回零的剩余帧、排队的急停及等待授权的连接；已提交到系统的帧无法撤销。旧操作不会被转发到新端口。
- 接口掉线或异常被检测到后，停止使用该 socket；恢复正常时可重新接入，但不重放控制命令。接口检查存在约一秒间隔，不构成机械臂安全监控。
- 同名端口拔插后会核对系统接口编号（ifindex），编号变化时重新绑定 socket 并取消旧操作。连接完成前启动的旧扫描结果不会覆盖新的连接状态；其他端口变化也不会重复输出当前端口的错误提示。

关闭窗口只关闭本面板 socket，不关闭系统 CAN、不发送额外指令。此工具不检查或协调其他 CAN 发送程序。

## 五个按钮

| 按钮 | 行为 |
| --- | --- |
| CAN 连接 | 按需激活选中接口，打开仅发送的 SocketCAN socket；不发送机械臂控制帧 |
| 机械臂使能 | 恢复 CAN / 普通 MOVE J 模式，发送 `471#0702000000000000`，等待六轴使能反馈确认 |
| 机械臂回零 | 普通 MOVE J，默认速度比例 10%，六轴目标角度均为 0°；确认使能与运动模式后发送目标 |
| 重置 | 发送一次 `150#0200000000000000`，即复位急停；留出约 1 秒处理时间后允许下一步 |
| 阻尼急停 | 底部整行红色按钮，发送一次 `150#0100000000000000` |

回零使用以下报文（以 can0 为例；面板先确认六轴已使能，再发送模式帧、等待模式反馈，最后发送三帧目标，不是无间隔执行这四条命令）：

```bash
cansend can0 151#01010A0000000000
cansend can0 155#0000000000000000
cansend can0 156#0000000000000000
cansend can0 157#0000000000000000
```

字段依据仓库内官方协议实现 `external/pyAgxArm/pyAgxArm/protocols/can_protocol/drivers/piper/default/parser.py` 的 `encode_151_mode_ctrl`、`encode_155_joint_ctrl_12`、`encode_156_joint_ctrl_34`、`encode_157_joint_ctrl_56`；运行时不导入 SDK。

回零指向控制器定义的零角度姿态，不修改零点标定，不自动使能、不自动重置、不进行避障或到位确认。速度可通过 `--home-speed 10` 设置（整数 1–100，默认 10）；这是控制器速度比例，不是固定角速度。执行前需现场确认零点定义、机械臂状态和活动空间。回零报文不是事务，急停、端口切换或发送失败可能留下已发送的部分帧；目标帧不自动补发或重试。

使能成功显示“CAN 运动模式和六轴使能已确认”；回零仍只报告“回零指令已发送”，不代表已经回到零位。重置不附带使能或回零。

### 急停后的恢复

1. 支撑好机械臂，点击“重置”，等待约 1 秒处理窗口结束。
2. 点击“机械臂使能”。面板先读取控制器状态，仍在急停时提示先重置；正常时重新建立 CAN / 普通 MOVE J 模式，并使能六轴。
3. 显示使能确认后，点击“机械臂回零”。面板再次确认六轴使能和模式；确认失败不会发送零角度目标。

依据 [官方对急停恢复的说明](https://github.com/agilexrobotics/piper_sdk/issues/20)，急停后需要先 reset，再设置运动模式；单发电机使能不等于恢复运动控制。旧版只发送一次使能，回零模式与目标紧接发送，也没有接收执行条件反馈。本次针对这些缺口补全恢复流程，但实机故障原因仍需结合现场结果确认。

临时接收 socket 只过滤 `0x2A1`（控制模式、急停/异常、MOVE 模式）与 `0x261–0x266`（各轴驱动器状态，byte 5 bit 6 为使能位），操作结束即关闭，不增加监控界面。字段来自仓库内官方 `arm_feedback_status.py`、`arm_feedback_low_spd.py`；普通 MOVE J 与六轴使能字段在已核对的默认/v188 协议中一致。

接收过滤器按 [SocketCAN 官方数据帧过滤规则](https://docs.kernel.org/networking/can.html#raw-socket-option-can-raw-filter) 设置为 `CAN_EFF_FLAG | CAN_RTR_FLAG | CAN_SFF_MASK`（`0xC00007FF`）。已修正旧版误把 `CAN_ERR_FLAG` 加入掩码而收不到正常状态帧的问题。2026-11-13 对 can0 做只读对比时，旧过滤器未收到报文；修复后用面板接收器被动采样 1 秒，收到 201 帧 `0x2A1` 和六轴各 20 帧驱动器状态。验证未发送控制指令，也未验证机械臂运动。

连接提示“CAN 已连接”表示网络接口和发送 socket 已接入；使能、回零仍会分别核对控制器反馈。收不到反馈时提示“未收到有效的机械臂状态反馈（0x2A1）”，反馈超时仍作为失败处理。

初始反馈最多等待 2 秒；恢复使能最多 3 秒，模式与使能以 100 ms 间隔有限重发，期间必须获得控制器正常、CAN / MOVE J 模式和六轴使能反馈。回零模式确认最多 2 秒；反馈缓存超过 0.5 秒不再视为有效。上述等待/重发参数是本工具的工程设置，不代表厂商保证的完成时间。缺失反馈、仍在急停、模式失败、未使能或驱动器异常都会明确报错。无反馈时不会退回盲发回零，也不会自动重置、绕过急停。

等待与重试可被急停、端口切换、接口掉线和关闭窗口取消；取消后不再补发恢复指令。重置的 1 秒等待不代表硬件复位已确认，之后的使能操作会重新读取实际状态。

急停使用独立发送路径，取消更早尚未发送的普通操作，并可中断回零剩余帧；后续按钮仍可点击；使能/回零是否能继续由本次读取的实际 CAN 状态决定，不增加持久的软件运动锁。重置可能解除保持，点击前确保机械臂得到支撑。阻尼急停不保证固定当前位置，软件按钮不代替物理急停。

## 文件与输出

| 文件 | 用途 |
| --- | --- |
| `run.py` | 入口；支持 `--demo`、`--home-speed`，以及仅演示模式可用的 `--screenshot 路径` |
| `app.py` | 端口选择、五按钮布局和操作结果 |
| `core.py` | 接口枚举/激活、精确帧构造、发送连接与临时过滤接收连接 |
| `backend.py` | 后台端口扫描、自动接入、可取消的操作发送 |
| `recovery.py` | 控制器状态解析、限时模式恢复、六轴使能确认 |

操作结果显示在窗口底部并输出到启动终端。截图参数将界面保存为图片后退出。演示模式提供 can0（UP）与 can1（DOWN）两个模拟端口，初始选中 can0，不访问真实 CAN。

[终端监控工具](../monitoring/README.md) 独立保留，不集成进面板。
