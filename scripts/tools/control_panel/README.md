# PiPER-L CAN 控制面板

面板负责 CAN 连接、机械臂使能、回零、重置和阻尼急停，直接使用 SocketCAN，不依赖 ROS 或 SDK。手柄、鼠标和规划任务的硬件准备统一从这里完成。

## 打开面板

在项目根目录运行：

```bash
bash scripts/piperl/run.sh --python-only python scripts/tools/control_panel/run.py
```

离线查看界面可加 `--demo`。运行需要 Linux SocketCAN、iproute2、Python、PyQt5 与 QtSvg，接口激活通过系统图形授权工具 pkexec。默认窗口 900 × 720；屏幕可用区域不足时缩小。窗口可调整大小。

## 窗口布局与离线预览

顶栏显示所选 CAN 端口、连接状态和接口速率。中部显示最近一次操作结果及“机械臂使能”。右侧使用 PiPER-L 本体模型生成的[静态线稿](../../../outputs/generated_images/control_panel/piper_l_sketch.png)，末端为裸法兰。故障信息或较窄窗口会让出图示空间以展示全文。回零与重置位于下方，红色阻尼急停固定在窗口底部。

窗口只保留当前状态和操作入口。将鼠标停在端口或按钮上可看操作说明；连接、回零、重置和停止的完整含义见下文。特别是：CAN 已连接不代表机械臂已使能；回零前确认活动空间，重置前支撑机械臂，软件阻尼急停不代替物理急停。

仅生成界面示例：

```bash
bash scripts/piperl/run.sh --python-only python scripts/tools/control_panel/preview.py
```

预览使用纯静态数据，不创建真实 Backend、不枚举端口、不打开 CAN、不提交操作。它在 `outputs/generated_images/control_panel/after/` 保存 900 × 720 和 720 × 640 的等待连接、已连接、处理中、长错误示例。这些截图只用于界面检查，不能作为连接、使能或动作证据。

## 连接与使能

1. 先结束使用同一机械臂的旧运动会话和驱动，再选择实际 CAN 适配器。
2. 选中接口未启用时，点击“连接”并完成系统授权。已启用、1 Mbps 且正常的接口会自动接入，不必重复连接。
3. 确认安装、支撑、活动空间和停止手段后，点击“机械臂使能”，等待“CAN 运动模式和六轴使能已确认”。
4. 再启动手柄或规划任务。官方驱动启动时读取使能状态，外部使能不保证刷新已运行驱动的缓存。

“CAN 已连接”只表示接口和发送 socket 可用，不代表已使能或可以运动。多个端口时等待明确选择，不自动切到第一个；保存的端口缺失时保留选择并提示，不改用另一机械臂。

面板可保留用于阻尼急停。运动会话中不要点回零、重置或重复使能，面板不协调其他 CAN 发送方。关闭面板不关闭系统 CAN、不发送额外控制，也不使电机失能。

## 五个按钮

| 按钮 | 行为 |
| --- | --- |
| 连接 | 按需启用选中接口、打开 socket，不发送机械臂运动指令 |
| 机械臂使能 | 恢复 CAN/普通 MOVE J 模式，等待控制器正常与六轴使能反馈 |
| 机械臂回零 | 确认使能与模式后，发送六轴零角度目标；默认控制器速度比例 10% |
| 重置 | 复位急停，留出约 1 秒处理窗口；不附带使能或回零 |
| 阻尼急停 | 独立发送路径，取消尚未发送的普通操作，可中断回零剩余帧 |

回零不修改零点标定，不自动使能、避障或确认到位。“回零指令已发送”不代表已回到零位。`--home-speed` 接受 1–100 的整数比例，不是固定角速度。回零不是手柄或规划的启动前置步骤。

阻尼急停不保证固定当前位置，有重力负载时仍可能移动。面板软件按钮不代替物理急停。重置可能解除保持，操作前确保机械臂得到必要支撑。

## 急停后的恢复

1. 结束旧手柄/规划会话和驱动，确认现场允许恢复并支撑好机械臂。
2. 点击“重置”，等待约 1 秒处理窗口结束。
3. 点击“机械臂使能”，等待重新确认 CAN/MOVE J 模式和六轴状态。
4. 再启动控制任务，按其要求重新建立会话或规划，不续跑旧命令。

只有确实需要并确认零位路径可行时，才单独使用回零。恢复流程不要求回零。反馈缺失、仍在急停、模式失败或驱动器异常都会报错，不退回盲发，不自动重置。

## 状态、文件与输出

端口每秒扫描。接口掉线、切换端口或关闭窗口会取消待发送操作，已进入系统的帧无法撤回。恢复正常可重新接入，但不重放旧控制。异常速率和 BUS-OFF 不会自动关闭或重配接口。

使能与回零期间临时读取 `0x2A1` 和 `0x261–0x266`，核对模式、异常与六轴使能；操作结束关闭接收 socket。等待和有限重发是工程设置，不是厂家保证的完成时间，也不构成持续安全监控。

| 文件 | 职责 |
| --- | --- |
| `run.py`、`app.py` | 参数、端口选择、按钮和结果显示 |
| `preview.py` | 静态数据离线界面截图，不创建 CAN 后端 |
| `core.py` | 接口枚举、激活、帧构造、发送与临时过滤接收 |
| `backend.py` | 后台扫描、自动接入与可取消操作 |
| `recovery.py` | 控制器状态、限时模式恢复与使能确认 |

结果显示在连接区下方的动态状态区和启动终端，故障文本不会截断。仅演示模式支持 `--screenshot 路径`，不会访问真实 CAN。被动监控独立位于 [monitoring](../monitoring/README.md)；离线检查入口见 [测试目录](../../../tests/README.md)。
