# 环境准备与维护

本页负责安装、构建与源码维护。日常使用从 [项目首页](../README.md) 选择入口。准备 Python 和构建工作区不需要连接机械臂。

## 环境组成

| 部分 | 约定 |
| --- | --- |
| 操作系统与 ROS | Ubuntu 24.04、ROS 2 Jazzy |
| Python | 系统 Python 3.12，项目 `.venv-piperl` 使用 `system-site-packages` |
| 系统依赖 | ROS、NumPy、SciPy、PyYAML、colcon 等由 APT 提供；本机版本快照见 [system_packages.txt](../config/system_packages.txt) |
| 官方源码 | SDK 位于 `external/pyAgxArm/`，ROS 与模型位于 `piperl_ws/src/agx_arm_ros/` 及其内部子模块 |
| 可选依赖 | `.deps/` 保存按需准备的 Servo、相机和标定依赖 |

项目复用系统 ROS/APT，不是完全独立的系统环境。项目入口清理外部环境变量，不使用 Conda，不修改 `.bashrc` 或全局 pip。

## 首次获取与构建

先准备好上述系统环境。`bootstrap.sh --online` 获取项目 Python wheel 并构建工作区，不负责安装整套系统 ROS/APT。

```bash
git clone --recurse-submodules https://github.com/lzc-datou/PiperL_Robot.git
cd PiperL_Robot
bash scripts/piperl/bootstrap.sh --online
bash scripts/piperl/run.sh python scripts/piperl/doctor.py
```

`bootstrap.sh` 核对锁定源码，创建虚拟环境，安装 Python 依赖与官方 SDK，最后调用 `build.sh`。`doctor.py` 检查软件环境，不连接机械臂。

主仓库 ZIP 不含子模块源码。克隆时未递归获取，或拉取主项目更新后，在项目根目录补齐锁定依赖：

```bash
git submodule update --init --recursive
```

模型 `agx_arm_urdf` 位于官方 ROS 仓库内部，因此需要 `--recursive`。

## 使用项目环境

各终端都通过 `scripts/piperl/run.sh` 运行项目命令，无需手动激活虚拟环境或重复 source 工作区。

| 入口 | 用途 |
| --- | --- |
| `run.sh <命令>` | 项目 Python、ROS Jazzy 与已构建工作区 |
| `run.sh --python-only <命令>` | 项目 Python，不加载 ROS/工作区；用于控制面板和离线工具 |
| `build.sh` | colcon 构建官方包与项目 ROS 包 |

默认 ROS Domain 为 43，发现范围为本机。专用 Domain 用 `PIPERL_ROS_DOMAIN_ID` 指定，同一控制栈的相关终端使用同一个值。手柄指南使用 Domain 64。Domain 不隔离物理 CAN。

`run.sh` 在项目根目录执行命令，文档示例也以根目录为起点。Python-only 不意味着没有硬件操作，控制面板正常模式仍使用真实 CAN。

## 修改后重新构建

更新 ROS 包、消息、插件或其配置后执行：

```bash
bash scripts/piperl/build.sh
```

结束旧窗口，再启动对应工具。源码、配置和插件不会自动替换已运行进程。

MoveIt Servo 可使用系统包或项目本地依赖，项目环境仅在本地前缀存在时加载它。准备方式见 [Servo 依赖说明](../scripts/task/servo_tracking/README.md#依赖与验证)。D405 和标定依赖见 [标定环境准备](../scripts/tools/handeye_calibration/README.md#1-环境准备)。

## 离线、更新与移机

已有源码、系统依赖和匹配 wheel 缓存时，可以离线准备：

```bash
bash scripts/piperl/bootstrap.sh --offline
```

`external/wheels/` 不随源码克隆分发，缓存缺失时先联网准备。换电脑或改变目录后，重新创建虚拟环境与构建结果，不直接复制旧 `.venv-piperl` 和 `piperl_ws/build/`、`install/`、`log/`。

官方依赖版本见 [source_versions.json](../config/source_versions.json)。主动升级时同步该记录、Git 子模块指针和可访问的远程来源，源码核对入口为：

```bash
python3 scripts/piperl/verify_sources.py
```

不要用 `git submodule update --remote` 代替获取锁定版本。子模块内修改需要在相应仓库保存和推送；使用 fork 时同步 `.gitmodules`。

## 运行输出

本机日志、点位、截图和验证 JSON 不随源码分发。输出目录与当前验证入口见 [项目结构](项目结构与控制接口.md#控制权退出与运行产物)和 [验证索引](README.md#当前验证与历史)。需要回归时选择对应记录的检查，不在正常操作的运动会话中运行集成脚本。
